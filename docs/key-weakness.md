# Key weakness (`--keys`)

The `keys` pass recovers the **public** keys in a target and reports any whose **private half is
obtainable**. It is the complement to the secrets pass: secrets/`derkey` find private keys that are
*present* in the image; this pass finds public keys whose private half is *recoverable* by an attacker.
Fully offline and compiled-in, like the boot pass. No network at scan time and no runtime table.

Two failure classes, following the standard taxonomy (see the research survey this was built from):

- **Disclosure** — a correctly generated private key that became public. Hardcoded/default SSH host and
  authorized keys shipped in appliances, the Vagrant insecure key, RFC/example keys reused in production.
  Detection is a fingerprint lookup against a curated corpus.
- **Generation** — the private key is computable from the public key because of bad randomness or
  structured primes. ROCA (CVE-2017-15361), structural weaknesses (undersized modulus, broken exponent),
  and the factoring recoveries that actually produce a factor: Fermat close primes, batch-GCD shared
  primes, and Wiener small-`d`. The factoring recoveries use a small in-tree bignum (`bigint.{hpp,cpp}`),
  the same zero-dep choice as SHA-256/CRC32/DEFLATE.

## What it recovers keys from

`src/pubkey.cpp`, text-anchored like the secrets engine because that is how firmware carries keys:

- **X.509 certificates** — PEM `CERTIFICATE`, and a whole-file bare DER cert. The `SubjectPublicKeyInfo`
  is located by trying each `tbsCertificate` child SEQUENCE (only the SPKI parses as one).
- **OpenSSH public keys** — `ssh-rsa` / `ssh-ed25519` / `ssh-dss` / `ecdsa-sha2-*` lines in
  `authorized_keys`, `*.pub`, `known_hosts`. Decoded from the SSH wire format (length-prefixed fields).
- **PEM/DER public keys** — a `SubjectPublicKeyInfo` or a bare PKCS#1 `RSAPublicKey`.
- **Private keys** — the public half (modulus `n`, exponent `e`) is pulled from PEM `PRIVATE KEY` blocks
  (PKCS#1 and PKCS#8 RSA), so an embedded private key is checked for weakness too.

For an RSA key it keeps the modulus `n` (big-endian, leading zeros stripped) and the exponent `e`; every
generation check keys on `n`. Non-RSA keys are still recorded so a disclosure (corpus) match still fires.
All DER parsing is a bounded ASN.1 TLV walk (shared shape with `certid.cpp`/`derkey.cpp`); base64 and the
SSH wire decode are bounds-checked. Keys with no issue are **not reported** (the pass stays high-signal).

## The three checks

### 1. Disclosure: leaked/default/hardcoded key (`leaked-key`, high, `validated`)

`src/keycorpus.cpp` is a compiled-in table of public keys whose private half is public, keyed by two
fingerprint namespaces:

- **`fp_ssh`** — SHA-256[0:32] of the raw OpenSSH public-key blob (exact-key match).
- **`fp_modn`** — SHA-256[0:32] of the RSA modulus, big-endian, no leading zeros (cross-container: the same
  key seen as a cert or a raw SPKI still hits). This is the same modulus fingerprint idea as badkeys'
  BKHASH120, so the corpus is compatible with the wider "HIBP for keys" ecosystem.

At scan time each recovered key's `fp_ssh` / `fp_modn` / `fp_der` are looked up. A hit reports the device
and the impact: a **host** key lets an attacker impersonate/MITM the device; an **authorized** key lets
them log in with the public-domain private key.

The corpus is generated by `tools/gen_keycorpus.py` from the vendored **public** keys under
`data/keycorpus/` (no private key is ever stored). Sources, all public and MIT-licensed:

- `rapid7/ssh-badkeys` `host/` + `authorized/` `.pub` files (hardcoded appliance keys; F5 BIG-IP, ExaGrid,
  Ceragon, Barracuda, Cisco, Comtrend, ..., many with a CVE).
- The HashiCorp Vagrant insecure key (private key published in the vagrant repo).

Regenerate after changing the vendored sources; `tools/gen_keycorpus.py --check` (wired into `run.sh`)
fails if `src/keycorpus_corpus.inc` is stale. See `THIRD_PARTY.md` for attribution.

### 2. ROCA fingerprint (`roca-key`, high, `validated`)

`src/keyweak.cpp`. Infineon RSALib (CVE-2017-15361) generated primes of a structured form, so the public
modulus alone is enough to factor it (a Coppersmith attack). The **fingerprint** that says a modulus is
vulnerable needs no factoring and no bignum: for each of a fixed set of small primes `p` (3..167, the
CRoCS set), `n mod p` must land in the multiplicative subgroup generated by 65537 mod `p`. One prime whose
residue is outside its subgroup is a **proof** the key is not ROCA; all inside is the fingerprint.

- `n mod p` is a byte-wise long division of the big-endian modulus by a machine word (`mod_be`); no
  multiprecision type is introduced.
- The per-prime residue masks are computed once from the 65537 subgroup and reproduce the published CRoCS
  `prints` constants by construction (the unit test pins `{3:6, 5:30, 7:126, 11:1026, 13:5658}`).

The actual Coppersmith factorization (recovering the private key) is Phase 2; the fingerprint match is what
this pass reports, and it is the same test the reference detector uses.

### 3. Structural weakness (`validated`/`structural`)

Computable from the public key with no factoring:

- `rsa-tiny-modulus` (high) — modulus < 1024 bits, factorable on commodity hardware.
- `rsa-weak-modulus` (medium) — 1024 ≤ bits < 2048, below the NIST floor. (Legacy 1024-bit CA roots in a
  trust store collapse to one deduped row in the human view.)
- `rsa-broken-exponent` (high) — `e` ∈ {0,1}: ciphertext equals plaintext.
- `rsa-even-exponent` (high) — `e` even: not a valid RSA key.
- `rsa-even-modulus` (high) — modulus divisible by 2: trivially factorable.

### 4. Factoring recovery (`fermat-factorable` / `shared-prime` / `wiener-weak`, high, `validated`)

These recover the actual private key from the public key, using the in-tree bignum (`bigint.cpp`: add,
sub, mul, bit-by-bit divmod, Euclid GCD, digit-by-digit isqrt, perfect-square test). A hit is a proof.

- **Fermat close primes** (`fermat-factorable`) — if `n = p*q` with `|p-q|` small, `n` factors near
  `ceil(sqrt(n))`. We step `a` up from there, checking `a^2 - n` for a perfect square (`a^2` tracked
  incrementally). Bounded to 100 steps (a tunable window; genuinely-close primes are found in a handful),
  so it is cheap per key. Catches the bad-RNG / shared-high-bits generation class (e.g. the
  CVE-2022-26320-style keys where `p` and `q` share their top half).
- **Batch-GCD shared prime** (`shared-prime`) — a cross-file post-pass (`main.cpp`) over every RSA modulus
  in the tree: if two distinct moduli share a prime, `gcd` recovers it and both are factorable. This is the
  offline, within-image form of the Mining-Ps-and-Qs finding (a vendor that generated a whole keyset with
  one starved RNG). Deduped by modulus (identical keys are reuse, not a shared prime) and bounded (≤256
  keys, moduli ≤16384 bits) so the O(n²) comparison cannot be turned into a DoS.
- **Wiener small-`d`** (`wiener-weak`) — continued-fraction convergents of `e/n`; a convergent denominator
  that yields an integer `phi` with a perfect-square discriminant recovers a small private exponent `d`.
  Only meaningful when `e` is large relative to `n` (a small `e=65537` is never Wiener-vulnerable), so the
  per-key gate skips the CF work otherwise. This is why the extractor keeps the full exponent bytes
  (`e_be`), not a `uint64`: a large `e` is normal and must not be misread as a broken (zero) exponent.

The per-key factoring checks (Fermat, Wiener) are guarded to `512 ≤ bits ≤ 16384` so an oversized modulus
cannot make a scan superlinearly slow.

## Output

Human mode prints a severity-sorted, deduped list (like the boot pass): `high`/`med`/`info` tag, the
finding type, the reason, and the key label + source path. JSON adds a `key_weakness` array of the standard
finding shape (type, category `keys`, confidence tier, evidence, label, description, offset). Keys with no
issue produce no finding.

## Testing

- `tests/unit/unit_tests.cpp::test_keyweak` — ROCA masks vs the published constants, `mod_be`, a ROCA
  positive (65537 itself, `g^1` mod every prime) and negative, the structural bands, corpus lookup, and an
  end-to-end `extract_public_keys` + `scan_keys` round-trip.
- `tests/test_keys.py` — the vendored corpus keys matched as `leaked-key` (host vs authorized impact), a
  CRT-constructed ROCA modulus flagged `roca-key`, 512/1024-bit RSA flagged structurally, a healthy
  2048-bit key and cert silent (false-positive guard), and a crash-safety sweep (truncations + mutations).
- The public-key parser is also exercised by `fuzz/fuzz_secrets` (it feeds `scan_keys`).

## Testing (Phase 2)

- `tests/unit/unit_tests.cpp::test_bigint` — the bignum: known-answer vectors against a Python oracle
  (add/mul/divmod/gcd/isqrt/perfect-square), edge cases (saturating subtraction, divide-by-zero guard,
  shifts, empty), and identity checks over 300 pseudo-random values (`q*d+r==n`, `0<=r<d`,
  `isqrt(x)^2<=x<(isqrt+1)^2`, `(a*b)/b==a`).
- `test_keyweak` adds Fermat (`10403 = 101*103`) and batch-GCD (`gcd(101*103, 101*107) = 101`) KATs.
- `tests/test_keys.py` constructs vulnerable keys with pure-Python prime generation: close primes →
  `fermat-factorable`, a small-`d`/large-`e` key → `wiener-weak` (and asserts the large `e` is not
  misreported as `rsa-broken-exponent`), and a shared-prime pair across two files → `shared-prime` on both.

## Remaining (deferred): Debian OpenSSL blocklist

The one Phase-2 item still deferred is the **Debian OpenSSL weak-key** set (CVE-2008-0166): a fingerprint
match against the (large) Debian blocklist, shipped as an optional mirrored asset via
`--fetch-db`/`--update-db` (a BKHASH120 sorted file read like `osvindex`) rather than compiled in. It needs
the mirror/refresh/CI-publish plumbing, so it rides the CVE-mirror workstream rather than this pass's
compiled-in corpus. The same mirrored-blocklist mechanism would also let batch-GCD run against a shipped
set of known-factorable moduli (the internet-scale Mining-Ps-and-Qs corpus), beyond the within-image GCD
already implemented.
